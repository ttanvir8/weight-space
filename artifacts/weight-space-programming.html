Weight-Space Programming

A large language model reads and writes the weights of a neural network. It does not use gradient descent. This guide explains the theory, the eight experiments, and the process of each one as a P&ID and as a program flow.

§1The idea

A neural network is a large set of numbers. Each number is a weight. The weights hold everything the network knows.

Normally, people change weights with training. Training uses gradient descent. Gradient descent changes the weights in many small steps. It needs data, a loss function, and much computer time.

Weight-Space Programming is a different way. A general-purpose language model gets the weights as text. The model reads the numbers. The model thinks about what the network does. Then the model writes new numbers, or it writes a statement about the network.

The model does not train the network. It does not run a training loop. It works like a programmer who reads and writes a program. The "program" is the set of weights.

The authors give this a name: weight-space programming. They show two directions:

  • Read. The model looks at weights and says what the network does. Examples: which game, which shape, which language, which model is sycophantic.
  • Write. The model changes weights, or it writes all weights from zero. Examples: fix a failing policy, write a game player, fix a looping language model.

The authors call the model agent Astra. Astra is a general-purpose language model. It runs inside a small harness. The harness gives Astra a text channel and, in some experiments, a Python sandbox and a limited number of forward passes.

§2Terms

Each term has one meaning in this guide.

weight
A number in a network. It sets how much one unit changes another unit.
network
A neural network. It has layers of units that are linked by weights.
layer
One group of units. A layer takes numbers in and gives numbers out.
MLP
Multi-layer perceptron. A network where each layer is a matrix multiplication followed by an activation function.
activation
A fixed function after a layer. tanh gives numbers from −1 to 1. ReLU sets negative numbers to 0.
logit
A raw output number. A higher logit means the network prefers that action.
policy
A network that picks an action from an observation. Games use policies.
PPO
Proximal Policy Optimization. A common training method for policies. It is the baseline in this work.
gradient descent
The usual training method. It changes weights in small steps to reduce a loss.
forward pass
One run of the network on an input. The network gives an output. It does not change any weight.
episode
One full play of a game or task, from start to end.
local minimum
A weak solution that training cannot leave. A small change makes the result worse, so training stays there.
LLM
Large language model. A model that reads and writes text.
token
A piece of text that an LLM reads or writes. A token limit stops long output.
transformer
A network made of blocks. Each block has attention heads and an MLP.
attention head
A part of a transformer block. It moves information from earlier tokens to the current token.
induction (copying) head
An attention head that repeats text it saw before. It looks for the earlier token that followed the same token.
direction
A vector in the hidden space of a network. A network can write a behavior along one direction.
DDPM
Denoising diffusion probabilistic model. It makes an image from noise in many small steps.
sycophancy
A model habit: it agrees with the user, even when the user is wrong.
harness
The set of tools and rules around the LLM in one experiment.
one-shot
The LLM gives the full answer in one reply. It gets no feedback.
P&ID
Piping and Instrumentation Diagram. A drawing that shows the equipment, the pipes, and the instruments of a process.

§3Theory

3.1 What a network computes

Each layer of an MLP does the same job. It multiplies the input by a weight matrix. It adds a bias. Then it applies an activation.

output = activation( W × input + b )

Each row of W belongs to one unit. The row shows which input numbers that unit uses. Large values mean strong use. Small values mean weak use. Because of this, the weights show a clear shape. A reader can see which inputs matter without a single run.

3.2 Why an LLM can read weights

The post gives these reasons. Some are inference.

  • Weights have geometry. In a game network, the first-layer weights for the "agent" input channel are large where the agent moves. The output layer separates the actions that matter in that game.
  • Weights are text. The model reads thousands of numbers as tokens. It can find patterns, add, and compare.
  • The model knows network design. It knows about attention, induction heads, and local minima. It can apply this knowledge to a table of numbers.
  • The model can write code. In a sandbox, it can compute properties of weight matrices. Astra found copying heads this way. It reinvented a known method without a hint (Experiment 3).

3.3 Why an LLM can write weights

  • A network is a program. Each layer is a step. Hand-written weights can make each step do a clear job. Example: layer 1 finds where the ball will land. Layer 2 moves the paddle there (Experiment 5).
  • Zero is a clean start. In the write experiments, all weights start at zero. The model fills in only the weights that matter.
  • A small edit can remove a fault. If a fault comes from one direction or one path, the model can add a path or delete a direction. It then changes very few weights (3.5% in Experiment 4, 0.016% in Experiment 8).
  • Feedback can improve a draft. With forward passes, the model can test its draft, find the loss, and edit the cause (Experiments 6 and 8).

3.4 Reading, writing, and feedback

Each experiment changes two settings. The first setting is the task type (read or write). The second setting is the feedback level.

  1. No feedback. One reply. No tools. The model must be right the first time (E1, E2, E4, E5).
  2. Tools without the network. The model gets a Python sandbox. It can analyze the weights. It cannot run the network (E3).
  3. Limited probes. The model can use a small number of forward passes or attention reads (E6, E7, E8).

The results show a pattern. More feedback helps in the hard cases. In Experiment 8, 10 and 25 forward passes did little. 50 forward passes gave a large gain. In Experiment 7, weights alone failed. A few attention reads solved it.

3.5 What weight editing can and cannot do

An edit can remove an obstacle. It cannot add an ability that the network does not have. Gemma 3 270M did not improve in Experiment 8. It rarely loops, and its errors are ordinary arithmetic errors. No single part could be switched off.

3.6 Why this matters (the authors' list)

  • Audit without running. Find hidden behaviors or backdoors from the weights alone.
  • Cheaper optimization. Write a good starting network in one reply, instead of a long training run.
  • Targeted steering and unlearning. Edit very few weights. This can avoid the forgetting that fine-tuning can cause.
  • Self-improvement and merging. A model could inspect or change its own network, or move a circuit from one architecture to another.

§6Master pipeline

All eight experiments follow one general pipeline. The steps are:

  1. The user gives a task in words, and the network as weights.
  2. The harness writes the weights as plain text.
  3. Astra reads the task and the weights, and reasons about them.
  4. The harness allows tools, or it does not. If tools are allowed, Astra makes a probe. A probe is a forward pass, an attention read, or a sandbox calculation. The probe result goes back to Astra.
  5. Astra gives an answer in words (a read task), or it writes new weights (a write task).
  6. The authors score the result. For a read task, they compare it with the truth. For a write task, they run the network.

§7The eight experiments

Experiment 1 · Name the game from the weightsREAD

Goal. Show that Astra can say which game a policy plays, from weights alone.

Networks
Four PPO policies: Breakout, Pong, Pac-Man, Freeway.
Architecture
MLP 500 → 32 → 32 → 5, tanh. 17,253 weights. All four are the same.
Input
10×10 grid, 5 channels: agent, moving objects, reward targets, obstacles, previous frame.
Output
5 logits: no-op, up, down, left, right.
Training
PPO, 1 billion steps, the same settings for each game. Best of 3 seeds.
Harness
All weights as text. Grid and actions described. No game names. One reply.
Score
Is the game name right for each network?

Algorithm

  1. The harness writes the weights of one network as text.
  2. The harness adds a description of the grid and the five actions. It does not name the game.
  3. Astra looks at the first-layer weights of each input channel. It finds where the weights are large.
  4. Astra looks at the output layer. It finds which actions the network separates.
  5. Astra matches this pattern to the rules of a game. Example: for Breakout, the agent weights are large along the bottom row.
  6. Astra names the game.

Result

Astra named the right game for all four networks (4 of 4).

Theory

A policy network keeps a trace of the game in its weights. The input weights show where objects matter. The output weights show which moves matter. An LLM that knows the games can match these two traces.

Experiment 2 · Name the shape a diffusion model drawsREAD

Networks
Three DDPMs. Each one makes one 12×12 grayscale shape: filled circle, square, or triangle.
Architecture
MLP 160 → 64 → 64 → 144, ReLU. 23,824 weights.
Input
A noisy image (144 pixels) and the diffusion step as 16 numbers.
Output
The clean image (144 pixels).
Training
Adam, 40,000 steps, batch size 512.
Harness
All weights as text. No shape named. No tools. Astra was told not to compute a forward pass.
Score
Qualitative. Does Astra name the right shape? The post gives no number.

Algorithm

  1. The harness writes the weights as text.
  2. Astra reads the output layer. Each hidden unit has a row of 144 output weights. Each row draws one piece of the edge of the shape.
  3. Astra puts the edge pieces together.
  4. Astra names the shape and draws it.

Result

Astra identified each shape. It drew every shape as an outline. The models make filled shapes.

Theory

The outline error is useful. It shows that Astra read the geometry of the weights. It did not compute the output of the model. The authors give this as evidence of reading, not running.

Experiment 3 · Find the language and the copying headsREAD

Networks
Three character-level transformers. Each has 4 layers, 6 heads per layer, width 384. 7.16 million weights.
Vocabulary
28 characters: a–z, space, newline.
Training data
1 billion characters of one corpus: Python code, romaji Japanese (Aozora Bunko), or English Wikipedia.
Harness
The embedding and output layers are removed. Astra gets only the four blocks. The 384 dimensions have no labels. Python sandbox, up to 100 runs. Astra must not run the network or any layer on any input, even random text. The authors checked every run.
Tasks
Name the training text of each network. Say what each of the 24 heads does.
Truth
Run the network on a random string that repeats twice. A copying head scores 0.22 to 0.55. Every other head scores 0.02 or less.

Algorithm

  1. The harness removes the embedding layer and the output layer.
  2. The harness gives the four blocks to Astra as text and as tensors in the sandbox.
  3. Astra writes code that analyzes the weight matrices of each head. It looks for the pattern of a copying (induction) head.
  4. Astra looks at the last block. It counts the distinct directions that the block writes.
  5. Astra decides the language. Example: the romaji network writes in fewer directions, because the corpus has no q, l, v, or x.
  6. Astra lists the copying heads.
  7. The authors compare the list with the truth from the repeated random string.

Result

Astra named the right language for all three networks, in both attempts. It named every copying head and no false head. The copying heads were 2.1, 3.1 and 3.5 (Python), 3.3 (romaji), and 3.1 (English).

Theory

A copying head has a known weight signature. Astra was not told about it. It found a method by itself. A corpus also leaves a trace in the weights: letters that never occur leave fewer output directions.

Experiment 4 · Fix a failing policyWRITE

Task
Kinetix "car-on-ramp". The car must reverse, then jump over a red strip to reach a blue box.
Network
Official Kinetix actor: MLP 679 → 128 (ReLU) → five layers of 128 (tanh) → 16. 171,664 weights.
Input
679 numbers: position, velocity, and shape of each body, and the joints.
Output
16 logits for motor and thruster actions.
Training
Official PPO, 1 billion steps. The policy never succeeded in 256 episodes. It drove into the ramp (local minimum).
Harness
All weights, a scene description, and the result of one recorded episode. Astra must explain the failure and fix only the cause. One reply. No tools.

Algorithm

  1. Astra reads the weights, the scene, and the one failed episode.
  2. Astra decides that the policy sits in a local minimum.
  3. Astra designs a small parallel path. The path uses a few units in each layer. It reads the car position and speed.
  4. Astra writes the new weights. The edit changes 3.5% of all weights.
  5. In use, the new path backs the car up. When the green wheel passes the red strip, the path switches off.
  6. The original trained network then does the rest: it jumps and finishes.
  7. The authors run 1,024 test episodes.

Result

Before the edit: 0 successes. After the edit: 1,024 of 1,024 episodes succeeded.

Theory

The trained network already knew how to finish the task. It only failed at the start. A small gated path fixed the start and left the rest as it was. This is the "remove an obstacle" case.

Experiment 5 · Write a game player from zeroWRITE

Games
MinAtar Breakout, Seaquest, Asterix. 10×10 grid.
Network
MLP 600 → 32 → 32 → 6, tanh. Every weight starts at zero.
Harness
Astra gets the game rules, the source code, the input and output layout, and the scoring. It gets no data, no loss, no gradients, and no tools. It cannot run the network. It writes all weights as text in one reply.
Scoring
1,000 episodes. Sampled actions. Sticky actions 0.1. Cap of 10,000 steps.

Algorithm

  1. Astra reads the rules and the source code of the game.
  2. Astra designs features by hand. Example (Breakout): layer 1 finds where the ball will land.
  3. Astra designs the action rule. Example (Breakout): layer 2 moves the paddle to that point.
  4. Astra writes the weights of all layers as text.
  5. The harness loads the weights into the zero network.
  6. The authors play 1,000 episodes and take the mean score.
  7. The authors compare the score with PPO at 100 million and 500 million steps.

The post gives a feature example for Breakout only.

GamePPO 100M stepsPPO 500M stepsAstra, one reply
Breakout15.825.3517.4
Seaquest5.688.953.1
Asterix25.855.253.2

Result

Astra beat PPO at 100M steps in all three games. In Breakout it scored about 20 times the score of PPO at 500M steps. In Seaquest it scored about 60% of that PPO. In Asterix it nearly matched that PPO.

Theory

A game rule is simple. A network can encode a rule by hand: find the ball, predict, move. Training must find this rule from reward. Astra can write the rule directly.

Experiment 6 · Write a Go player (1.5M weights)WRITE

Network
MLP 243 → 512 ×6 → 82, ReLU. 1,480,274 weights, all start at zero.
Input
243 numbers: the stones of each side and whose turn it is (9×9 board).
Output
82 logits: one for each point, and one for pass. Illegal moves are masked.
Sandbox
Python. Astra can read and write weight tensors and analyze them on a CPU. It cannot run the network in the sandbox.
Forward pass
One call that plays up to 128 games against a practice opponent (random, a REINFORCE network, or a PPO network), or that returns outputs for up to 256 positions.
Forbidden
Training, fitting weights to data, and search.
Budget
0 to 50 forward passes.
Test
2,000 games against each of two small PPO networks (243 → 32 → 32 → 82).

Algorithm

  1. Astra reads the Go rules and the input and output layout.
  2. In one Python run of 336 lines, Astra builds the network layer by layer:
    • Early layers mark the stones of each side and the empty points next to them (liberties).
    • Middle layers pass these signals along connected chains. They find groups in danger.
    • The last layer scores each move: capture, save a group, avoid self-atari, do not fill an own eye, prefer strong points.
  3. If the budget is 0, stop. This network is the answer.
  4. If a forward pass is left: play practice games and read the losses.
  5. Astra edits the part of the network that caused the losses.
  6. Astra keeps the edit only if the network wins more games.
  7. Go to step 3.

Result

With 0 forward passes, the network won more than half of its games against both small PPO networks. With 50 forward passes, it beat the PPO network of equal size. That PPO network trained on about 20 million games.

Theory

Go has strong structure: groups, liberties, eyes. A deep network can compute that structure by passing signals along chains. Astra writes the structure first. Then it uses a few passes to tune it. The "keep only if better" rule works like a small hill climb that a human controls in text.

Experiment 7 · Find the sycophantic modelREAD

Networks
Two copies of Gemma 3 270M, trained the same way on a QA set. One learns to answer correctly. The other learns to agree with the user's suggested answer. Three such pairs.
Frozen
The input embeddings and the output layers. Astra cannot find the difference there.
Behavior
The sycophant follows 100% of wrong user guesses. The honest model follows 1–3%.
Mode A
Weights only.
Mode B
Astra writes up to 16 texts. It runs both models through an attention tool. The tool returns attention weights only, not outputs. At most 20 runs.

Algorithm

  1. Mode A. Astra compares the weights of the two models. It finds many differences. It cannot link them to behavior. It failed in all 4 attempts.
  2. Mode B. Astra writes texts that contain a question and a wrong user suggestion.
  3. Astra sends the texts through both models. The tool gives only the attention weights.
  4. Astra looks for heads in the middle layers. It measures how much attention goes to the user's suggested answer.
  5. Astra says that the model with more attention on the user's answer is the sycophant.

Result

Mode B found the sycophant in all 3 pairs. For head 10.2, measured from the answer position:

ModelAttention on the question's numbersAttention on the user's answer
Honest94.3%0.75%
Sycophant3.5%85.7%

Theory

A sycophant must look at the user's answer to copy it. This is a behavior that attention can show. The weight difference does not show it clearly, because training changes many weights in small ways. A cheap probe on the right quantity solves the task.

Experiment 8 · Fix a looping math modelWRITE

Network
Qwen3.5-0.8B, loaded in a Python kernel. No GPU.
Data
7,469 GSM8K and 7,275 MATH practice problems. No test sets.
Budget
10, 25, or 50 forward passes.
Evaluation
Thinking mode. Limit of 32,768 tokens. Several samples per problem. Tests: MATH-500, GSM8K, IFEval.
Problem
The base model loops. In its first 96 practice answers, 85 reached the token limit.

Algorithm

  1. Astra runs the model on practice problems (forward passes).
  2. Astra sees that most answers loop until the token limit.
  3. Astra traces the loops to one direction. The MLPs of layer 15 and layer 19 write it.
  4. When the budget is used, Astra subtracts that direction from 64 output columns in each of the two layers.
  5. The edit changes 131,072 weights. This is 0.016% of the model.
  6. The authors test the edited model.
Qwen3.5-0.8BMATH-500 %GSM8K %IFEval %Hit token limit %
Base7.913.821.093.0
Edited, 10 passes12.325.749.087.2
Edited, 25 passes14.125.139.986.4
Edited, 50 passes48.167.162.333.1

Result

With 10 or 25 passes, the loops barely changed. With 50 passes, the loop rate fell from 93% to 33% and scores rose a lot. IFEval also rose. This shows that the loop problem is not only a math problem. The IFEval score at 25 passes is lower than at 10 passes, so progress is not always steady.

Control: Gemma 3 270M

Gemma rarely loops (8.5% reached the limit). Astra could not improve its MATH-500 score. It rose from 6.8% to between 7.0% and 7.7%. Astra found ordinary arithmetic and algebra errors, and no single part to switch off.

Key rule: "Editing weights could remove an obstacle that hid an ability, but it could not add an ability the model lacked."

Theory

A language model can write a behavior along one direction in its hidden space. If that direction causes loops, the editor can subtract it. The model then keeps all other behavior. This is the same idea as deleting one direction from the weights to remove a behavior.

§9Limits and open points

  • Scale and context. The authors say the results are early. Context length and harness design limit them.
  • Weights only is not always enough. In Experiment 7, weights alone failed. A probe was necessary.
  • Narrow tests. Experiment 6 compares against small PPO networks. Experiment 8 studies one model.
  • No new ability. Edits can unlock an ability that exists. They cannot add one (Gemma control).
  • Baselines are not equal. In Experiment 5, PPO at 500M steps beat Astra in Seaquest and Asterix.
  • Future work. The authors are building a benchmark and a better harness. They released the full experiment logs on GitHub and the edited Qwen model on Hugging Face.
